# 海岛夺金数值模拟：编辑型研究界面重设计

日期：2026-08-19

## 1. 目标

将现有数值模拟器从常规运营后台风格升级为克制、专业的“编辑型研究工具”，让策划人员围绕地图推进、行动力、战斗、积分与联盟平衡快速形成判断。

本次只重构信息架构、视觉表达与结果阅读体验，不改变已经验证的仿真规则、参数含义或结果口径。所有现有功能必须保留：120 项参数调整、单次/批量仿真、随机种子与结果复现、地图回放、排行榜、玩家积分事件及联盟统计。

## 2. 已确认的设计方向

- 总体布局：C，编辑型混合布局。
- 字体：A，文献衬线标题与高可读无衬线正文组合。
- 图表：B，低饱和联盟色、细线、弱网格、直接标注。
- 地图：C，注释图版；地图仍是页面主视觉。
- 参数面板：C，目录式检视器；所有参数继续统一位于左侧。
- 公开交付：GitHub 作为代码源，Cloudflare Workers 自动部署，访问者无需登录。

## 3. 视觉语言

### 3.1 色彩

- 页面底色采用暖灰白，而非纯白。
- 正文与主要线条采用炭黑，避免传统后台的大面积蓝色强调。
- 联盟颜色使用低饱和蓝、红、金，仅承担数据身份，不承担装饰。
- 地图保持深色图版，以形成页面唯一的高对比视觉焦点。
- 成功、风险与警告仅用于诊断结论，不把整页做成彩色状态面板。

### 3.2 字体与数字

- 页面标题、章节标题、关键数值使用中文衬线字体栈，形成研究出版物气质。
- 控件、表格、长文本使用现代中文无衬线字体栈，保证密度和可读性。
- 数值使用等宽数字特性；单位字号小于数字，不使用夸张的大号 KPI 卡片。
- 字重控制在常规到半粗之间，层级主要依靠字号、留白和分隔线建立。

### 3.3 容器与线条

- 取消大量浮起卡片、厚阴影、彩色底块和圆角胶囊。
- 主要模块以留白、细分隔线和小幅圆角划分。
- 图表、表格和解释文本共享统一基线与内容宽度。

## 4. 页面信息架构

### 4.1 顶部

- 左侧为“海岛夺金 数值模拟”与简短说明。
- 中部为六个功能页签：仿真总览、行动力与占领、战斗与士气、任务与奖励、积分与回放、玩家与联盟排名。
- 右侧保留当前种子、复现入口与“运行仿真”主按钮。
- 页签只切换结果视图；参数编辑始终在左侧统一管理。

### 4.2 左侧参数检视器

- 固定宽度桌面侧栏，标题直接使用“参数调整”。
- 顶部提供搜索、恢复默认和校验状态。
- 采用两级结构：参数章节目录 + 当前章节控件。
- 章节目录显示基础参数、人口与战力、活跃度、行动力、占领、战斗、士气、玩家策略、任务、奖励、目标等分组。
- 当前章节只展示对应控件，避免 120 个字段同时形成连续长墙。
- 任务数组使用紧凑表格行；数值字段继续使用原生输入控件并保留已有边界、步长和校验。
- 草稿参数与已运行参数继续隔离；未重新运行前，结果区明确提示存在未应用修改。

### 4.3 主结果区

视觉顺序固定为：研究问题与诊断 → 地图图版 → 趋势图表 → 明细证据。

地图在所有与战局相关的页面中保持最大视觉权重。其他图表不得抢占地图首屏中心，也不得使用过重图标或装饰。

## 5. 核心结果指标

顶部不再展示“活跃战线”“中心争夺占比”“计算耗时”等普通后台指标。核心摘要必须直接回答数值决策问题：

1. 首次有效 PvP：展示本局时间；批量结果展示 P50 与 P10–P90 区间，并对照目标窗口。
2. 地图价值差：三联盟当前占领价值的最大相对差距，用于判断推进失衡。
3. 行动力浪费率：因达到上限、无合法目标等原因未转化为有效行动的 AP 比例。
4. 中心争夺强度：结合中心交战、易手和持续控制时间形成可解释指标，并提供原始分项。
5. 积分集中度：前 10% 玩家获得的积分占比，并补充战力与积分相关性。

摘要下方生成一句“本局诊断”，用中性语言指出最值得关注的偏差，例如 PvP 时间、中心收益或高战力积分效率风险。诊断必须由结果数据计算，不使用固定文案伪装分析。

计算耗时、事件数量、种子等信息降级到页脚或运行详情。

## 6. 地图图版

### 6.1 几何与地格

- 延续现有无明显缝隙的尖顶六边形几何和正确地图数据。
- 地格通过底色、简洁地形纹样和小型符号区分平原、山地、水域、资源点、先锋营、出生点与中心核心。
- 联盟占领色覆盖必须保留地形辨识度；不把全部地格涂成难以识别的纯联盟色块。

### 6.2 注释层

- 左侧注释当前关键战斗、首次 PvP、中心易手或异常推进事件。
- 右侧注释当前联盟占领价值、中心控制状态与高价值争夺点。
- 注释采用细引导线和短句，不遮挡地图主体。
- 回放滑杆控制地图、占领价值、联盟积分曲线和玩家积分流水的统一时间截面。

### 6.3 状态表达

- 清晰表达所有权、交战、占领进度、队列、驻防和高价值资源。
- 悬停/键盘焦点显示地格类型、坐标、价值、所有者、交战双方、队列和剩余时间。
- 回放至任意时间时，所有数值必须只使用该时间之前的事件，禁止泄露最终结果。

## 7. 图表系统

- 使用 SVG 或现有轻量绘图实现，不引入视觉沉重的图表框架。
- 曲线采用 1.5–2px 低饱和联盟色；非核心对照线使用炭黑与浅灰。
- 网格线极淡，只保留必要刻度；尽量在线尾直接标注联盟或指标，减少大型图例。
- 重点图表包括联盟总体积分曲线、占领价值曲线、行动力供需/浪费、中心控制时间、积分分布与战力—积分关系。
- 图表标题必须说明它帮助判断什么，而不仅是重复字段名。
- 地图旁仅放与当前时间截面直接相关的小型图表；其他图表置于地图之后。

## 8. 积分与回放

- 联盟积分趋势与地图共用同一回放时间。
- 玩家选择器支持搜索并默认选择有代表性的活跃玩家。
- 玩家积分台账分为战功、占领和总积分；头部累计值由当前时间之前的事件实时求和，不读取终局汇总。
- 每条事件包含时间、来源、得分、对手/地格以及当时的累计值。
- 联盟身份、名称和颜色必须与地图及排行榜完全一致。

## 9. 响应式与可访问性

- 桌面端保持左侧检视器 + 主内容；地图优先获得宽度。
- 900px 以下参数检视器变为可关闭抽屉，关闭时使用 inert/aria-hidden 并管理焦点。
- 640px 以下摘要指标纵向排列，地图保持可横向查看或自适应，不压缩到无法辨认。
- 图表提供可读标题和数据摘要；地图画布保留键盘导航与文本提示。
- 所有颜色信息同时辅以文字、线型或符号，不以颜色作为唯一识别方式。

## 10. 状态与性能

- 每次“运行仿真”默认产生新的随机种子；“复现当前种子”使用当前已应用种子重跑。
- 仿真继续在浏览器本地运行，不上传策划参数或模拟事件。
- 运行期间显示明确的计算状态，但不故意添加虚假延迟。
- 大量积分事件按当前玩家和回放时间增量筛选；图表使用按时间桶聚合后的数据，避免一次渲染全部原始事件。
- 结果对象保持可复现；视觉层不得重新随机或篡改结果。

## 11. 公开部署

- 公开 GitHub 仓库只包含数值模拟器及其说明，不包含内部文档、机器人源码、路径、凭据或项目隐私信息。
- 使用 Cloudflare Workers 的 Vinext 原生部署链，连接 GitHub 主分支自动构建。
- 生产网址使用公开 `workers.dev` 地址；后续可选绑定自定义域名。
- 普通访问者无需 ChatGPT、GitHub 或 Cloudflare 账号。
- 部署前执行敏感信息扫描、完整测试、lint、生产构建与站点就绪检查。

## 12. 验收标准

- 视觉上符合已认可的最终整合稿：编辑型混合布局、文献衬线、低饱和图表、注释地图、目录式参数检视器。
- 120 项参数均可找到、修改、校验、恢复默认并影响下一次仿真。
- 所有既有仿真、回放、排名、随机/复现与积分流水功能保持可用。
- 五个核心摘要均由真实结果推导，并随重新仿真或回放时间正确变化。
- 地图是首要视觉，不被 KPI 卡片或图表淹没。
- 联盟颜色与名称在地图、图表、积分台账、排名中一致。
- 任意回放时刻不泄露未来积分或终局占领值。
- 桌面与移动布局、键盘焦点、抽屉语义通过组件测试。
- 全量测试、lint、生产构建、公开站点就绪检查全部通过。

## 13. 非目标

- 不修改已经确认的战斗、士气、行动力、占领、任务和奖励公式。
- 不引入账号、数据库、排行榜后端或多人协作功能。
- 不制作重动画、大面积渐变、3D 地图或游戏客户端式装饰。
- 不将内部策划案、机器人行为源码或任何敏感项目资料发布到公开仓库。
